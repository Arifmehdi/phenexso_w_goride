 1. WHAT THIS PROJECT IS
--------------------------------------------------------------------------------
 A ride-hailing platform with FIVE user types, each with their own login
 and their own database table (separate auth guards, not roles on one table):

   - User       (passenger / "solo" rider)
   - Driver     (independent driver)
   - Owner      (fleet owner — owns vehicles, drivers work under them)   *
   - Corporate  (company account — books rides for employees, gets billed)
   - Admin      (platform operator)

   * NOTE: "Owner" is implemented as a User with role=owner + vehicles.owner_id,
     NOT a separate table/guard. Only Driver, Corporate and Admin are separate
     Eloquent models/tables from User. Keep this in mind — auth()->user() is
     the DIRECT model for whichever guard logged in (see section 4.3, this
     bit caused real bugs earlier and must stay top of mind for new code).

 Core loop: passenger requests a ride -> nearby online drivers get a push
 "ride call" -> first driver to accept wins the job -> live GPS tracking
 both ways -> trip stages (accepted -> arriving -> in_progress -> completed)
 -> payment (cash / wallet / card / bKash-Nagad) -> both sides rate each other.

 Real-time matching runs on Firebase Firestore (NOT polling the Laravel DB),
 while Laravel/MySQL is the system of record for accounts, fares, payments,
 ratings, and reporting. This dual-system design is intentional — do not
 try to replace Firestore with Laravel polling, it will not be fast enough
 for live location updates.

 3.5 Known backend fragility — READ THIS BEFORE EDITING ROUTES:
     routes/api.php and routes/web.php previously had class references with
     their namespace backslashes stripped, e.g.
        [AppHttpControllersApiDriverRatingController::class, ...]
     instead of
        [\App\Http\Controllers\Api\DriverRatingController::class, ...]
     This is a FATAL error that crashes EVERY route in the app (not just
     the broken one) the moment Laravel tries to boot, and `php -l` CANNOT
     catch it (it's valid PHP syntax, just references a class that doesn't
     exist). ONLY `php artisan route:list` catches it. This has already
     happened twice in this project (once from original legacy code, once
     from a backup/file restore wiping recent edits). Whoever edits routes:
       - ALWAYS use fully-qualified \App\Http\Controllers\... with backslashes
       - ALWAYS run `php artisan route:list` after touching routes/*.php,
         not just `php -l`
     Also: PromoCodeController's method is named checkCode(), NOT validate()
     — naming it validate() collides with Laravel's built-in Controller
     trait method and fatals at class-load time. Don't rename it back.

 3.6 Config / .env keys — what's set vs. what needs a real value:
     ALREADY WORKING (sandbox defaults, no .env entry needed):
       - SSLCommerz: SSLCZ_STORE_ID_TEST / SSLCZ_STORE_PASSWORD_TEST are in
         .env and set to a real sandbox account (works for test card payments)
       - ShurjoPay: config/shurjopay.php has hardcoded sandbox creds
         (sp_sandbox / testpass) — works without touching .env

     MISSING / NEEDS A REAL VALUE:
       - FIREBASE_CREDENTIALS (or place the file at the default path

         push notifications to work when the app is backgrounded.
       - APP_URL is currently "http://northbengal.test/" — WRONG for this
         project, breaks the public trip-share links. Set to your real
         local/production URL.
       - No SMS gateway configured — OtpController currently just writes
         the OTP code to storage/logs/laravel.log (search "OTP for").
         Fine for internal testing, must be replaced before real users.
       - SSLCZ_STORE_ID_LIVE / SSLCZ_STORE_PASSWORD_LIVE are empty — fill
         these before going live with real card payments.
       - No FCM_SERVER_KEY needed (legacy field, the app uses the modern
         v1 API via the service-account JSON above instead).

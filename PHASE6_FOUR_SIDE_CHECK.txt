================================================================================
 HOW TO CHECK EACH SIDE (step by step)
================================================================================

 A) WEB ADMIN — easiest, do this first
    1. Start Laragon (Apache+MySQL running).
    2. Browser: http://localhost/goride/public/login → log in with an
       admin account.
    3. Visit each page: /admin/dashboard, /admin/users, /admin/approvals,
       /admin/drivers, /admin/vehicles, /admin/promo-codes, /admin/banners,
       /admin/websiteparam, /admin/ride-matching.
    (On your live server replace localhost/goride/public with your domain.)

 B) API — for the endpoints that have no screen yet
    1. Get a token:
       curl -X POST http://localhost/goride/public/api/login \
            -H "Accept: application/json" \
            -d "login=ADMIN_EMAIL" -d "password=PASSWORD"
       → copy the "token" from the reply.
    2. Call any admin endpoint:
       curl http://localhost/goride/public/api/admin/dashboard-stats \
            -H "Accept: application/json" -H "Authorization: Bearer TOKEN"
       Same pattern for /api/admin/active-rides, /api/admin/reports/revenue,
       /api/admin/support-tickets, /api/admin/surge, /api/admin/payouts/pending.

 C) FLUTTER APP (rider/driver side)
    Run the app → book/complete rides, apply promo TEST10, check the home
    banner, open Help & Support and create a ticket, check fare changes
    after editing per_km_rate on the web panel.

 D) FLUTTER ADMIN AREA
    Log in as admin in the app → Admin panel. Expect: management screens
    and summary numbers are still DEMO data (see ❌ items above) — that is
    the accurate current state, not a bug in your test.
